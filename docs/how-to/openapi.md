# OpenAPI integration

SparseTypes provides separate integrations for ASP.NET Core's built-in OpenAPI support and Swashbuckle. Both packages target .NET 10 and require the `SparseTypes` package so its source generator can produce schema metadata for each model's `ChangePayload`.

Install `SparseTypes.OpenApi.AspNetCore` to use the built-in OpenAPI support, or `SparseTypes.OpenApi.Swashbuckle` to use Swashbuckle. Add the corresponding namespace to the application.

## ASP.NET Core OpenAPI

Register the generated payload type with `AddSparseOpenApi<TPayload>()`. Map and publish the document using the standard ASP.NET Core APIs:

<!-- illustrative: Order is an application model generated by SparseTypes. -->
```csharp
using SparseTypes.OpenApi.AspNetCore;

builder.Services.AddOpenApi();
builder.Services.AddSparseOpenApi<Order.ChangePayload>();

var app = builder.Build();
app.MapOpenApi();
```

## Swashbuckle

Register the generated payload alongside Swashbuckle's normal services:

<!-- illustrative: Order is an application model generated by SparseTypes. -->
```csharp
using SparseTypes.OpenApi.Swashbuckle;

builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();
builder.Services.AddSparseOpenApi<Order.ChangePayload>();
```

## Registered schemas

Registration adds the payload envelope, its change union, and generated change DTOs to `components.schemas`, including DTOs that no endpoint uses. The change union has a `member` discriminator mapped to the root and member change schemas. Endpoint schemas use the same deterministic component naming as the registration metadata.

Calling `AddSparseOpenApi<TPayload>()` more than once is supported. Register each model whose payload should appear in the document. The component names are based on the model's namespace, containing type, and generated role; generated implementation hashes are omitted.

The runtime schema contract and component-name helper are available in the `SparseTypes` namespace as advanced APIs. OpenAPI adapters use these contracts so naming and generated schema metadata are shared by both integrations.

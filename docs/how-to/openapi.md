# OpenAPI integration

SparseTypes provides separate integrations for ASP.NET Core's built-in OpenAPI support (`SparseTypes.OpenApi.AspNetCore`) and Swashbuckle (`SparseTypes.OpenApi.Swashbuckle`), plus a JavaScript and TypeScript client generator (`@sparsetypes/codegen`). Both .NET packages target .NET 10 and require the `SparseTypes` package so its source generator can emit schema metadata (`T.PayloadJson.Schema`) for each model's `ChangePayload`.

Install `SparseTypes.OpenApi.AspNetCore` to use the built-in OpenAPI support, or `SparseTypes.OpenApi.Swashbuckle` to use Swashbuckle. Add the corresponding namespace to the application.

## ASP.NET Core OpenAPI

Register the generated payload schema bundle with `AddSparseOpenApi(Order.PayloadJson.Schema)`. Map and publish the document using the standard ASP.NET Core APIs:

<!-- illustrative: Order is an application model generated by SparseTypes. -->
```csharp
using SparseTypes.OpenApi.AspNetCore;

builder.Services.AddOpenApi();
builder.Services.AddSparseOpenApi(Order.PayloadJson.Schema);

var app = builder.Build();
app.MapOpenApi();
```

## Swashbuckle

Register the generated payload schema bundle alongside Swashbuckle's normal services:

<!-- illustrative: Order is an application model generated by SparseTypes. -->
```csharp
using SparseTypes.OpenApi.Swashbuckle;

builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();
builder.Services.AddSparseOpenApi(Order.PayloadJson.Schema);
```

## Registered schemas

Registration adds the payload envelope, its model change union, root snapshot, member delta schemas, and any nested `[SparseModel]` payload bundles to `components.schemas`. Each generated component also includes an `x-sparsetypes` extension that records the model name, schema identity (`sha256:...`), and member metadata (shape, nullability, wire type, comparison mode, and keyed collection identity).

`MembersDelta` schemas declare `additionalProperties: false`, so an unknown addressed member target is rejected by schema validation exactly as the C# payload reader rejects it during JSON parsing. Forward-compatible unknown *metadata* fields remain allowed at the envelope, operation, item, and endpoint levels.

Calling `AddSparseOpenApi(...)` more than once is supported. Register each root model whose payload should appear in the document. Component names are based on the model's namespace, containing type, and generated role; generated implementation hashes are omitted.

## Model-to-DTO associations

Each `ChangePayload` component carries an `x-sparsetypes` extension. In addition to the static build-time metadata (`version`, `role`, `model`, `schemaIdentity`, `membersComponent`), the ASP.NET Core and Swashbuckle integrations publish an explicit `dto` property that names the ordinary OpenAPI DTO component for the payload's model (for example, `"dto": "OrderDto"`). Both integrations emit equivalent metadata for OpenAPI 3.0 and 3.1.

The DTO component is resolved from the application schema pipeline, never invented:

1. An explicitly registered external schema for the model type wins.
2. Otherwise the component the application's schema ID policy assigned to the model CLR type itself is used (this accounts for custom schema ID selectors and same short class names across namespaces).
3. When the model type has no component in the document (for example, a `204` response or a wrapper result DTO that never exposes the raw model), `dto` is omitted.

Because the association follows the model type rather than any single operation's response shape, it stays correct for `204` responses, wrapper result DTOs, multiple media types, and endpoints whose response is not the request model. Nested models resolve the same way, so a keyed line model maps to its own DTO component independent of its parent operation.

The runtime schema contract (`SparsePayloadSchemaBundle`, `SparsePayloadSchema`) and component-name helper (`SparsePayloadSchemaNames`) are available in the `SparseTypes` namespace as advanced APIs. OpenAPI adapters use these contracts so naming and generated schema metadata are shared by both integrations.

## Generate a JS/TS client

[![npm Version](https://img.shields.io/npm/v/@sparsetypes/codegen?style=flat-square&logo=npm)](https://www.npmjs.com/package/@sparsetypes/codegen)

`@sparsetypes/codegen` reads an OpenAPI 3.0 or 3.1 JSON document that includes SparseTypes schema metadata and generates a dependency-free ES module with TypeScript declarations.

### Prerequisites for client generation

1. Register each root model's `PayloadJson.Schema` on the server with `SparseTypes.OpenApi.AspNetCore` or `SparseTypes.OpenApi.Swashbuckle`.
2. Associate each `ChangePayload` request with its ordinary DTO response schema in the OpenAPI document (for example, a `PUT` or `PATCH` endpoint that accepts `OrderDto.ChangePayload` and returns `OrderDto` in a `2xx` response). Nested `[SparseModel]` types are matched automatically from the parent DTO properties.
3. Export the OpenAPI document to a JSON file during build or development.

> [!NOTE]
> Models with custom C# equality comparers (`[SparseCompare]`) are rejected by `@sparsetypes/codegen` because JavaScript cannot reproduce custom C# equality semantics on the client.

### Install and run

Install `@sparsetypes/codegen` in a Node.js 20+ project and run the `sparsetypes-codegen` CLI against the OpenAPI JSON file:

```bash
npm install --save-dev @sparsetypes/codegen
npx sparsetypes-codegen ./openapi/order-api.json
```

By default, files are emitted to `node_modules/@sparsetypes/generated` with an internal `package.json` so your application can import from `"@sparsetypes/generated"` without extra path aliases. Pass `--output <directory>` to write the generated files to a custom directory:

```bash
npx sparsetypes-codegen ./openapi/order-api.json --output ./src/generated
```

You can also invoke the generator from a build script:

```ts
import { generate } from "@sparsetypes/codegen";

await generate({
  input: "./openapi/order-api.json",
  output: "node_modules/@sparsetypes/generated",
});
```

### Generated files and exports

| File | Generated exports | Purpose |
|---|---|---|
| `api.d.ts` | `paths`, `components`, `operations` | Full OpenAPI TypeScript declarations emitted via `openapi-typescript`. |
| `models.js` / `models.d.ts` | `type {Model}`, `type Optional{Model}`, `type DeepOptional<T>`, `type DeepReadonly<T>`, `parse{Model}(value)` | DTO type aliases, deep-optional state types for diff inputs, and runtime validators that check unknown values against the OpenAPI component schema. |
| `changes.js` / `changes.d.ts` | `build{Model}ChangePayload(before, after)` | Computes a version `"0.1"` `ChangePayload` envelope between `before` and `after` states, or returns `undefined` when no tracked members changed. |
| `client.js` / `client.d.ts` | `createClient(options?)`, `ApiError`, `type ApiClient`, `type ClientOptions`, `type {Operation}Args` | `fetch`-based HTTP client with typed methods (`{operation}(args, init?)` and `{operation}Raw(args, init?)`) for every OpenAPI operation. |
| `index.js` / `index.d.ts` | Re-exports from `client`, `changes`, and `models` | Package entry point (`@sparsetypes/generated`). |

### Build and send a `ChangePayload` from TypeScript

Use `parse{Model}` to validate the server DTO, edit a draft state, and pass the baseline and draft to `build{Model}ChangePayload`:

```ts
import {
  ApiError,
  buildOrderDtoChangePayload,
  createClient,
  parseOrderDto,
  type OptionalOrderDto,
} from "@sparsetypes/generated";

const api = createClient({ baseUrl: "https://example.test" });

const baseline = parseOrderDto(
  await api.getOrder({ params: { path: { id: 1 } } }),
);

const draft: OptionalOrderDto = {
  ...baseline,
  name: "Updated order",
  items: [
    ...baseline.items,
    {
      id: 0,
      clientTempKey: crypto.randomUUID(),
      productName: "Keyboard",
      quantity: 1,
      unitPrice: "49.95",
    },
  ],
};

const body = buildOrderDtoChangePayload(baseline, draft);
if (body) {
  try {
    const saved = parseOrderDto(
      await api.saveOrder({
        params: { path: { id: 1 } },
        headers: { "If-Match": `"${baseline.version}"` },
        body,
      }),
    );
  } catch (error) {
    if (error instanceof ApiError && error.status === 409) {
      console.error("Concurrent conflict:", error.body);
    }
  }
}
```

### Client diff rules

`build{Model}ChangePayload(before, after)` follows the same wire contract as the C# `ChangePayload` serializer:

- **Presence vs null**: Omitted properties and properties set to `undefined` produce `{"state": "missing"}`. Explicit `null` produces `{"state": "null"}`.
- **Keyed collections (`[SparseKey]`)**: Items are matched by their permanent key (`key`), or by their `[SparseTemporaryKey]` UUID (`temporaryKey`) while the permanent key holds its unassigned default (`0`, `""`, or the empty UUID). Added, updated, removed, and reordered items include `beforeIndex` / `afterIndex` and `beforeOrder` / `afterOrder` (plus `tempBeforeOrder` / `tempAfterOrder` when temporary keys are present).
- **Redacted before-states (`[SparseRedactBefore]`)**: Members configured with `redactBefore` always emit `{"state": "redacted"}` for the `before` endpoint.
- **Precision-sensitive scalars (`decimal`, `long`, `ulong`)**: `Optional{Model}` accepts either a `string` or a safe `number`. Equal decimal values with different scale strings (such as `"12.50"` and `"12.5"`) compare equal and do not emit a redundant change.

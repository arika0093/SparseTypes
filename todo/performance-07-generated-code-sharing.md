# 07 Model-neutral generated code sharing

## Initial inspection

`SparseTypes.Generator.Shared` contains product-neutral emitters, but each generated model still receives model-specific copies of transition and patch machinery. The earlier partitioner change moved generated members without changing emitted bytes, so it did not reduce generated source size. Any source reduction must be measured by generated file count, source bytes, and lines across multiple model counts, and must account for shared implementation overhead.

The Shared project is compiled into consuming generators as source. Its emitters must remain independent of the SparseTypes runtime and express product-specific type/member names through existing configuration and dialects.

The captured pre-change generator baseline reports 6 files, 380,414 source bytes, 4,335 lines, and a 147,456-byte assembly for 1 model; 21 files, 1,345,925 source bytes, 14,946 lines, and a 399,872-byte assembly for 4 models; and 81 files, 5,211,167 source bytes, 57,390 lines, and a 1,500,672-byte assembly for 16 models.

For keyed model payloads, the baseline reports 11 files, 979,191 bytes, 10,451 lines, and a 330,752-byte assembly for 1 model; 26 files, 2,793,255 bytes, 28,691 lines, and a 797,696-byte assembly for 4 models; and 86 files, 10,053,039 bytes, 101,651 lines, and a 2,732,544-byte assembly for 16 models.

The tracked Shared C# implementation is a fixed generator-side baseline. Its reproducible current count is 196 C# files, 59,382 newline-terminated lines, and 2,754,679 source bytes; the earlier first-pass count in this report was off by 2 lines and 22 bytes.

## Repair plan

Measure emitted output for 1, 4, and at least 16 models, along with generator/shared implementation size. Identify repeated code that can safely move to one model-neutral generated helper without changing model-specific APIs or adding a large abstraction. Compare emitted files and bytes before and after; reject any change whose source-size savings are negligible relative to generated shared code or runtime overhead. Run focused generator tests, Shared formatting checks, and the isolated packed Shared consumer probe without a SparseTypes runtime reference.

## Disposition

### Closed: keyed duplicate guards are factored with an amortized source-size reduction

The initial partitioner-only check below found no source reduction. A focused follow-up then factored the repeated keyed duplicate check into a generated-once helper. That helper keeps the generated `map.Add(key, value)` after validation, so the value expression remains unevaluated on duplicate keys. It accepts the map itself, preserving its comparer and `ContainsKey` behavior; it does not use `TryAdd`, callbacks, or a new runtime dependency.

The product injects the helper name through `SparsePatchDialect`. Shared emits the BCL-only helper beside the existing removal index, and unconfigured downstream dialects retain inline guard emission. The shared implementation changes are in `SparseGeneratedOnceRemovalIndex.cs`, `SparseGeneratedOnceNames.cs`, `SparseFragmentPatchEmitter.cs`, and the keyed patch, transition, and rebase emitters under `Emitters/Patch/`. `SparseTypesGenerator.cs` supplies the product-owned generated helper name. The existing generated-once tests assert that the guard precedes `map.Add`.

The before/after size harness is `artifacts/performance-all/generated-line-count/Program.cs`; results are in `artifacts/performance-all/generated-line-guard-after.json`. File counts are unchanged. Collection output is also unchanged. Keyed model output changes as follows:

| Models | Files before → after | Source bytes before → after | Byte delta | Lines before → after | Assembly bytes before → after |
|---:|---:|---:|---:|---:|---:|
| 1 | 11 → 11 | 979,191 → 979,654 | +463 | 10,451 → 10,463 | 330,752 → 331,264 |
| 4 | 26 → 26 | 2,793,255 → 2,792,695 | −560 | 28,691 → 28,703 | 797,696 → 797,184 |
| 16 | 86 → 86 | 10,053,039 → 10,048,387 | −4,652 | 101,651 → 101,663 | 2,732,544 → 2,730,496 |

The helper adds 804 generated bytes and 12 lines inside the existing generated-once file; it adds no file. The factoring grows the one-model output, reaches a 560-byte net source saving at four models, and saves 4,652 bytes at sixteen models. The Shared C# implementation grows from 196 files, 59,382 lines, and 2,754,679 bytes to 196 files, 59,457 lines, and 2,758,945 bytes: +75 lines and +4,266 bytes. The savings therefore apply to repeated keyed output, not to the generator package itself.

The targeted runtime check reuses the 2,048-item keyed `ChangeSet.Between` ShortRun reference. OneEdit measured 88.267 µs / 336.4 KB before and 89.353 µs / 336.4 KB after. AllEdits measured 98.469 µs / 528.47 KB before and 104.369 µs / 528.47 KB after. The after-run 99.9% confidence margins were 22.574 µs and 35.35 µs, respectively. Allocation was unchanged; this short run does not establish a CPU regression.
